## Close policy

An entry in this ledger changes status **only** when one of these is true and
is backed by evidence **and** tests:

- **Fixed** — the remediation is implemented and covered by a test that would
  fail without it (mutation/red-green where practical), and the change is on
  the branch (or released).
- **Removed** — the offending code/claim/asset was deleted or retired, with
  caller/usage proof (e.g. caller-grep for dead code) and the relevant tests
  green.
- **Refuted** — the finding was demonstrated false against code or external
  tool behavior, with the evidence recorded (e.g. PDF-1 / PDF-4).

"Implemented on the unreleased branch" is a *pending* state, not a close. An
entry remains **Open** until the branch ships (v3.0.0 tag/release) **and** the
evidence/tests named in the close criteria are present.

Status vocabulary: `Open` · `Fixed (on branch, unreleased)` ·
`Removed (on branch, unreleased)` · `Refuted`. All entries are Open pending the
release gate; the parenthetical states record branch progress only.
